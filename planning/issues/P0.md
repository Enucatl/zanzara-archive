## Bounded steps

1. Track all native children, including later Sol remediation issues; each must complete its acceptance evidence and required merged PRs.
2. Invoke `$review-phase <this-issue-number>` under GPT 5.6-Sol after integrated work is ready. Verify the report names the actual reviewed commit and current reference/model/evaluation artifacts.
3. Resolve every blocking finding, rerun Sol for changed code/evidence, then request the user's explicit `Release P0 at <reviewed-commit>` comment.
4. Only after that comment, close this parent as completed and set Project Status Done. The next phase remains blocked until then.

## Inputs, outputs and failure behavior

Inputs are completed children, merged PRs, current code and real phase evidence. Output is a human release record tied to the current Sol PASS and commit. Failed criteria or missing evidence keep this issue open and Blocked; PASS awaiting user release is In review. New relevant code or findings invalidate an older PASS.

## Exclusions

No automatic parent closure, waived thresholds, inferred approval or execution of the next phase. A closed-not-planned prerequisite is not completion without an explicit user-approved replacement.

Stop at this gate if any child/follow-up, target, current review or explicit release is missing. Completion means all checklist items are satisfied and the user has released the reviewed phase.
