- Stable ID: P1-08
- Executor: Luna

## Outcome and requirement

Reviewed golden reference/split and locked local pipeline; output real baseline report and resource measurements.

## Design and interfaces

Use [E2](../EVALUATION.md#e2--asr-diarization-attribution-and-timing-metrics), [E6](../EVALUATION.md#e6--operational-measurements-and-report-format), [E7](../EVALUATION.md#e7--gates-and-expansion-checks) and the existing contracts/modules produced by completed prerequisites. The implementation issue establishes only interfaces within this scope; preserve compatible earlier contracts. See [execution rules](../GITHUB-SETUP.md#g7--luna-implementation-handoff-and-release-rules) for selection and evidence.

## Prerequisites

Parent: [P1](P1.md). Required completed blockers: [P0](P0.md), [P1-06](P1-06.md), [P1-07](P1-07.md). The preceding phase must have a current Sol PASS and explicit user release. This issue does not depend on its own parent closing.

## Bounded steps

1. Freeze configuration before held-out scoring and execute the golden local pipeline through the worker.
2. Measure E2 metrics/slices and E6 timing, memory, failures and cost; distinguish development, held-out and full-episode values.
3. Publish sanitized aggregate results and private detailed artifact references with exact commands and reviewed commit.

## Inputs, outputs and failure behavior

Reviewed golden reference/split and locked local pipeline; output real baseline report and resource measurements. Preserve source/model/configuration provenance in outputs and fail without publishing partial artifacts when validation fails. Missing review, insufficient evidence or failed targets prevents baseline acceptance.

## Exclusions

No cloud requests, hidden tuning on held-out outcomes or automatic phase closure.

## Acceptance checklist

- [ ] Held-out normalized WER <=25% and zero-collar overlap-inclusive DER <=25%.
- [ ] Every required metric includes denominators, source/reference/model hashes and measured hardware context.
- [ ] Failed targets create concrete remediation under P1 and block phase release.
- [ ] Required evidence below is linked and applies to the reviewed commit/configuration.

## Verification commands

```bash
uv run zanzara evaluation run --suite golden --reference "$ZANZARA_REFERENCE" --split "$ZANZARA_GOLDEN_SPLIT" --output "$ZANZARA_RESULTS"
```

Add the named focused tests/CLI commands in this issue if they do not yet exist; P0-01 establishes common uv/Ruff/pytest commands. Run relevant CPU checks plus the explicitly required real GPU/integration/evaluation actions. Do not treat a mocked model response as measured model quality.

## Evidence and documentation

Record exact commands/results, reviewed commit, artifact/source/model/split hashes where applicable, and the private evidence path. Update the relevant interface/runbook documentation for implemented behavior. Public issues and comments contain sanitized aggregate results and synthetic examples only. Commit the bounded change directly to `main`, push `origin/main`, verify the remote commit, and comment with outcome, checks, limitations and evidence. Set this child issue to Done only after all acceptance items pass. For execution-only evaluation, commit the sanitized report/runbook changes and link private detailed artifacts.

## Stop conditions and completion rule

Missing review, insufficient evidence or failed targets prevents baseline acceptance. Complete only after the required commit is pushed to `main` and every acceptance item is satisfied; a local or unpushed commit is not completion. Keep [P1](P1.md) open for Sol review and user release.
