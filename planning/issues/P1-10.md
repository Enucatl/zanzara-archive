# [P1-10] Prefer niquests and minimize HTTP client dependencies

- Stable ID: P1-10
- Executor: Luna
- Kind: Implementation
- Parent: P1
- Blocked by: P0

## Outcome and requirement

Audit and reduce the repository's HTTP-client footprint. Prefer `niquests` for
new and existing application-managed HTTP calls whenever it supports the
required behavior, and avoid direct `httpx` or `requests` dependencies and
imports wherever a compatible migration is practical.

The task must distinguish direct production dependencies, framework-required
test dependencies and transitive lockfile dependencies. A justified exception
may remain when replacing it would break a supported framework contract or add
more risk/weight than it removes, but the exception and its dependency path
must be recorded.

## Design and interfaces

Use the repository's existing Python/`uv` packaging and internal HTTP adapter
boundaries. Inventory root application code, service code, tests, Docker build
metadata and all lockfiles before changing dependencies. Migrate compatible
application/provider/worker clients to `niquests`, preserving timeouts, TLS
verification, proxy behavior, streaming, retries, response validation and
request accounting.

Do not replace stable standard-library HTTP code solely to make a nominal
client count smaller. Do not remove a framework's required test client without
providing an equally supported ASGI test transport. No credentials or real
paid requests are needed for this task.

## Prerequisites

Parent: [P1](P1.md). Required completed blocker: [P0](P0.md). The preceding
phase must have a current Sol PASS and explicit user release. This issue does
not depend on its own parent closing.

## Bounded steps

1. Inventory every direct and transitive `httpx`, `requests` and `niquests`
   occurrence, identifying production, test-only, framework and transitive
   uses.
2. Define the smallest repository policy: `niquests` is preferred for
   application-managed HTTP; direct `requests`/`httpx` use requires a written
   exception; unavoidable transitive packages are tracked separately.
3. Migrate compatible application-managed clients and remove obsolete direct
   dependencies without changing service contracts or network security
   behavior.
4. Re-lock affected environments with `uv`, inspect the resulting dependency
   graph and update Docker/runtime documentation.
5. Run focused HTTP adapter tests and the complete CPU test suite, recording
   any framework or transitive exceptions.

## Inputs, outputs and failure behavior

Inputs are the current Python packages, service packages, lockfiles, HTTP
adapters and test harnesses. Outputs are the bounded client migrations, lock
updates, dependency inventory, documented exceptions and verification report.
Preserve TLS, timeout, retry and response/error semantics; fail the task if a
migration silently weakens those behaviors, introduces duplicate clients or
causes unaccounted dependency growth.

## Exclusions

No unrelated dependency refresh, provider/model change, paid request, broad
network redesign, or forced replacement of a standard-library client without
a concrete compatibility or maintenance benefit.

## Acceptance checklist

- [ ] A complete inventory separates direct production, test-only, framework
      and transitive HTTP-client dependencies.
- [ ] `niquests` is used for compatible application-managed HTTP clients, and
      direct `requests`/`httpx` uses have been removed or explicitly justified.
- [ ] Affected `uv.lock` files and Docker metadata contain no accidental
      duplicate client installation; dependency-size impact is recorded.
- [ ] TLS, timeout, retry, streaming and response-validation behavior remains
      covered by tests or a documented compatible exception.
- [ ] Full CPU verification passes and the sanitized inventory/evidence is
      linked to the reviewed commit.

## Verification commands

```bash
rg -n "httpx|requests|niquests" pyproject.toml services src tests docs
uv tree
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Run equivalent `uv tree` and test checks in each affected service environment.
Do not treat a clean import test as proof that network semantics were
preserved.

## Evidence and documentation

Record exact inventory commands/results, changed files, direct/transitive
dependency paths, lockfile hashes, exception rationale, test results, reviewed
commit and private evidence paths where applicable. Public comments contain
only sanitized dependency and test summaries; never publish credentials or
private network traces.

## Stop conditions and completion rule

Stop with a documented blocker if `niquests` cannot provide a required client
capability without weakening behavior, if a framework requires `httpx`, or if
the migration increases runtime/image size without an accepted reason.
Complete only after the implementation commit is pushed to `main`, all
acceptance evidence is current and the task is ready for integrated Sol review.
Keep [P1](P1.md) open for review and user release.
