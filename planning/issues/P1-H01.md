# [P1-H01] Operator: accept model terms and provision download access

- Stable ID: P1-H01
- Executor: Human
- Kind: Operator
- Parent: P1
- Blocked by: P0

## Outcome and requirement

The six fixed model candidates; output human access/terms evidence and private credential availability.

## Design and interfaces

Use [D5](../SYSTEM-DESIGN.md#d5--models-and-adapters) and the existing contracts/modules produced by completed prerequisites. The implementation issue establishes only interfaces within this scope; preserve compatible earlier contracts. See [execution rules](../GITHUB-SETUP.md#g7--luna-implementation-handoff-and-release-rules) for selection and evidence.

## Prerequisites

Parent: [P1](P1.md). Required completed blockers: [P0](P0.md). The preceding phase must have a current Sol PASS and explicit user release. This issue does not depend on its own parent closing.

## Bounded steps

1. Review each candidate license and access terms, including gated Community-1 and the fine-tuned WavLM checkpoint/head.
2. Accept required terms through the operator account and provision credentials via private environment/secret files.
3. Record model access granted/denied, reviewer, date and source URLs without secrets; confirm RTX 5090 access for P1-01.

## Inputs, outputs and failure behavior

The six fixed model candidates; output human access/terms evidence and private credential availability. Preserve source/model/configuration provenance in outputs and fail without publishing partial artifacts when validation fails. Denied/unavailable access blocks P1-01; do not replace the checkpoint.

## Exclusions

No Luna acceptance of legal terms, model substitutions or benchmark inference.

## Acceptance checklist

- [ ] A human records access/terms decisions for every candidate.
- [ ] Required download credentials are available to model acquisition but absent from repository and public issue comments.
- [ ] Required evidence below is linked and applies to the reviewed commit/configuration.

## Verification commands

Operator evidence: dated access/terms checklist; P1-01 performs authenticated download and GPU verification.

The operator performs the action/review; CLI validation checks format and completeness, never substitutes for human judgment. If a required validation command is missing, request a bounded Luna follow-up rather than pretending this Human task implemented it.

## Evidence and documentation

Record exact commands/results, reviewed commit, artifact/source/model/split hashes where applicable, and the private evidence path. Update the relevant interface/runbook documentation for implemented behavior. Public issues and comments contain sanitized aggregate results and synthetic examples only. Include the human actor, action date and explicit decision; never publish credentials or private annotations.

## Stop conditions and completion rule

Denied/unavailable access blocks P1-01; do not replace the checkpoint. Complete only when the human action and acceptance evidence are recorded. Keep [P1](P1.md) open for Sol review and user release.
