## Outcome and requirement

Release **Measured transcription and diarization baseline** only after integrated behavior, current evidence and user review satisfy this phase. This parent is a human release gate, never an unattended Luna implementation issue.

parent retains the completed production services, model/runtime provenance and

or a timestamp-capable ASR as a release condition. The migration map and
preserved issue history are recorded in [P1R-01-MIGRATION](../P1R-01-MIGRATION.md).

## Bounded steps

1. Track all native children, including later Sol remediation issues; each must complete its acceptance evidence and required implementation commits pushed to `main`.
2. Invoke `$review-phase <this-issue-number>` under GPT 5.6-Sol after integrated work is ready. Verify the report names the actual reviewed commit and current reference/model/evaluation artifacts.
3. Resolve every blocking finding, rerun Sol for changed code/evidence, then request the user's explicit `Release P1 at <reviewed-commit>` comment.
4. Only after that comment, close this parent as completed and set Project Status Done. The next phase remains blocked until then. P1R is released separately as the transcription-quality phase.

## Inputs, outputs and failure behavior

Inputs are completed children, implementation commits pushed to `main`, current code and real phase evidence. Output is a human release record tied to the current Sol PASS and commit. Failed criteria or missing evidence keep this issue open and Blocked; PASS awaiting user release is In review. New relevant code or findings invalidate an older PASS.

## Exclusions

No automatic parent closure, waived thresholds, inferred approval or execution of the next phase. A closed-not-planned prerequisite is not completion without an explicit user-approved replacement.
