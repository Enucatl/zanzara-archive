# [P1R-01] Supersede legacy evaluation design and migrate planning contracts

- Stable ID: P1R-01
- Executor: Luna
- Kind: Implementation
- Parent: P1R
- Blocked by: P0

## Outcome and requirement

Make P1R the authoritative transcription-quality methodology and retire only the obsolete P1 evaluation contracts. Preserve completed services, artifacts, issue bodies and comments.

## Design and interfaces

Audit every authoritative plan, manifest, release gate and live dependency mentioning the golden episode, five-block split, 200 timed words, timing-error gate, mandatory `TimedWord`, or old P1 evaluation gates. Record explicit P1R replacements before changing any legacy issue state.

## Bounded steps

1. Update planning contracts to name chunk gold, episode-level partitions, optional timing metadata and separate ASR/diarization/attribution evaluation.
2. Reconcile downstream dependencies that require transcription evidence, beginning with P2, without renumbering phases.
3. Mark only methodology-specific P1 review follow-ups superseded/not planned, linking P1R replacements; retain history and reusable implementation.

## Inputs, outputs and failure behavior

Input is the existing planning package and live P1/P2 issue graph. Outputs are versioned planning changes, a migration record and exact live issue/dependency evidence. A remote/body/relationship conflict blocks mutation and is reported.

## Exclusions

No removal of Parakeet, Community-1, native timestamps, production attribution, speaker embeddings, or unrelated downstream metrics.

## Acceptance checklist

- [ ] No active transcription release gate requires manually timed words or a timestamp-capable ASR.
- [ ] P1 review follow-ups changed only after their P1R replacement is linked.
- [ ] P2 and applicable later dependencies name P1R rather than the obsolete P1 gate.
- [ ] Historical issues/artifacts remain accessible and explicitly non-authoritative.

## Verification commands

Run `node planning/validate.mjs`; read back all changed GitHub issue bodies, states, native blockers and Project fields with GITHUB-SETUP G6 commands.

## Evidence and documentation

Record a before/after dependency map, issue URLs/states, planning commit, and the exact legacy clauses superseded.

## Stop conditions and completion rule

Stop on a three-way body conflict, unsupported native edge, or ambiguity about a non-ASR downstream dependency. Complete after authoritative planning and live records agree without deleted history.
