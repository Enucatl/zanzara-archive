# [P1R-03A] Community-1-aware adaptive chunk boundary selection

- Stable ID: P1R-03A
- Executor: Luna
- Kind: Implementation
- Parent: P1R
- Blocked by: P0, P1R-02, P1R-03, P1-03

## Outcome and requirement

Replace the boundary-selection logic of the already implemented P1R-03 chunker with a deterministic Community-1-aware algorithm.

The new algorithm must create practical human-review chunks around 12 seconds long while preferring natural conversational boundaries.

Use the existing `pyannote/speaker-diarization-community-1` standard diarization as the sole speech-activity and speaker-transition source.

Do not introduce a separate VAD model.

Do not use any ASR model or transcript text to determine chunk boundaries.

## Design and interfaces

## Bounded steps

1. Add versioned Community-1 standard-turn boundary extraction and ranking while
   preserving existing chunk identities and storage compatibility.
2. Add deterministic synthetic coverage for all ten specified cases.
3. Rebuild the development batch and record boundary diagnostics and rerun
   hashes before human inspection.

## Why this variant exists

P1R-03 already exists with a different segmentation algorithm.

P1R-03A is an explicit variant/replacement of its boundary-selection strategy.

Preserve the existing chunking infrastructure, storage contracts and interfaces where compatible.

Only replace the boundary-generation/ranking behavior required by this issue.

Do not silently rewrite unrelated P1R-03 behavior.

## Fixed segmentation parameters

Use these initial values exactly:

```text
preferred_min_ms = 8_000
target_ms        = 12_000
preferred_max_ms = 18_000
hard_max_ms      = 30_000

strong_gap_ms    = 600
short_gap_ms     = 250

speaker_change_tolerance_ms = 250
overlap_margin_ms            = 250

minimum_chunk_ms = 4_000
```

All values must live in versioned configuration rather than being scattered as literals.

Changing any of these values creates a new segmentation configuration fingerprint.

## Speech activity source

Use Community-1 **standard diarization**, not exclusive diarization, to determine speech activity.

Definition:

```text
speech active
= at least one standard-diarization speaker active

speech gap
= interval during which zero standard-diarization speakers are active
```

This preserves true overlap information.

## Speaker-change definition

A speaker change occurs when:

```text
speaker A is active immediately before boundary
and
speaker B is active immediately after boundary
and
A != B
```

For implementation purposes, a speech-gap midpoint is considered to coincide with a speaker change when the last active speaker before the gap differs from the first active speaker after the gap.

For near-contiguous turns without a true gap, a speaker-turn transition is a candidate when the outgoing and incoming speaker boundaries occur within:

```text
speaker_change_tolerance_ms = 250 ms
```

## Speech-gap classes

Classify each zero-speaker interval as:

```text
strong gap:
    duration >= 600 ms

short gap:
    250 ms <= duration < 600 ms

ignored micro-gap:
    duration < 250 ms
```

Micro-gaps below 250 ms must not independently create chunk boundaries.

This avoids turning tiny diarization discontinuities or conversational micro-pauses into excessive chunk fragmentation.

## Boundary point inside a gap

For a speech gap selected as a boundary, use:

```text
midpoint of the gap
```

rounded deterministically to integer milliseconds.

Do not use the start or end of the gap unless the midpoint would violate episode bounds.

This leaves some silence on both adjacent chunks and avoids clipping speech tightly.

## Candidate types and fixed priority

Candidates are ranked first by **boundary class**, then by distance from the 12-second target.

Use this exact priority order:

```text
Priority 1:
    strong_gap + speaker_change

Priority 2:
    strong_gap

Priority 3:
    clean_speaker_change

Priority 4:
    short_gap + speaker_change

Priority 5:
    short_gap

Priority 6:
    hard_maximum

Priority 7:
    episode_end
```

`episode_end` is special: if the remaining episode duration is short enough to form the final chunk, it terminates the episode rather than competing normally with earlier natural candidates.

## Preferred search interval

Given current chunk start `S`:

```text
preferred candidate interval:
    [S + 8_000 ms, S + 18_000 ms]
```

Search all natural candidates whose timestamp lies inside this interval.

If one or more candidates exist:

1. select the highest-priority candidate class;
2. among candidates of that class, choose the one with minimum absolute distance from:

```text
S + 12_000 ms
```

3. if still tied, choose the earlier timestamp.

This tie-breaking order is mandatory.

## Extension beyond preferred maximum

If no natural boundary exists between 8 and 18 seconds, continue searching for natural candidates in:

```text
(S + 18_000 ms, S + 30_000 ms]
```

In this extension region, use the same candidate priority order.

However, once beyond 18 seconds:

* select the **earliest candidate in the highest available priority class**;
* do not continue delaying toward 30 seconds merely to approach another preferred target.

The goal after 18 seconds is to end the chunk at the first reasonable natural opportunity.

## Hard maximum

If no acceptable natural boundary exists before:

```text
S + 30_000 ms
```

create a boundary at exactly:

```text
S + 30_000 ms
```

with reason:

```text
hard_maximum
```

unless episode end occurs earlier.

No generated chunk may exceed 30 seconds.

## Overlap avoidance

A candidate is considered overlap-conflicted if its boundary timestamp lies:

```text
inside an interval with >=2 active standard speakers
```

or within:

```text
250 ms
```

before or after such an overlap interval.

Natural candidates inside this overlap exclusion margin are normally rejected.

Exception:

If rejecting all overlap-conflicted candidates would force a hard-maximum boundary, the chunker may use the best overlap-conflicted natural candidate before hard max.

In that case persist:

```text
boundary_overlap_conflict = true
```

This is preferable to an arbitrary cut at 30 seconds when a recognizable conversational transition exists nearby.

## Speaker-change candidates during overlap

Do not create an ordinary `clean_speaker_change` candidate when multiple speakers remain simultaneously active across the transition.

A clean speaker change requires:

* one dominant/outgoing active speaker before;
* one different active speaker after;
* no overlap conflict within the 250 ms exclusion margin.

True overlapped transitions belong to overlap handling, not clean speaker-change handling.

## Minimum chunk length

Ordinary chunks must be at least:

```text
4_000 ms
```

However, preferred candidate search still begins at 8 seconds.

The 4-second minimum exists only for special cases such as final episode remainder handling.

Never create a 4–8 second chunk merely because an attractive pause occurs there during ordinary segmentation.

## Final episode remainder

If episode end occurs before the next 8-second preferred minimum:

* append the remaining audio to the previous chunk if doing so keeps that previous chunk at or below 30 seconds;
* otherwise create a final short chunk.

A final short chunk below 4 seconds is permitted only when merging it into the previous chunk would exceed the 30-second hard maximum.

Persist the final-boundary reason as:

```text
episode_end
```

and record whether the final chunk is below the ordinary minimum.

## Contiguous coverage

Chunks must cover the selected episode region contiguously.

For all adjacent chunks:

```text
chunk[n].end_ms == chunk[n+1].start_ms
```

Do not discard silence.

Do not shift original timestamps.

Do not overlap neighboring chunks.

## Stable chunk identity

Chunk identity must be deterministic from at least:

```text
source identity
start_ms
end_ms
segmentation configuration fingerprint
```

Do not use database insertion order or random UUID generation as the sole identity source.

## Deterministic candidate ordering

For every candidate, build a comparable tuple equivalent to:

```text
(
    candidate_priority,
    selection_distance_rule,
    boundary_timestamp_ms
)
```

No random ordering is permitted.

The same source diarization and configuration must yield byte-identical chunk manifests.

## Required synthetic test cases

Tests must explicitly cover the following.

### Case 1 — ideal strong pause near target

```text
chunk start: 0
strong gap: 11.7–12.5 s
```

Expected boundary:

```text
12.1 s midpoint
reason = strong_gap
```

### Case 2 — strong gap with speaker change beats closer ordinary gap

Example:

```text
ordinary strong gap midpoint: 11.9 s
strong gap + speaker change midpoint: 13.0 s
```

Expected:

```text
13.0 s
```

because class priority beats target-distance preference.

### Case 3 — clean speaker change

No gap >=250 ms.

Speaker A ends and B begins around 12.4 s.

Expected:

```text
speaker_change
```

if outside overlap exclusion margin.

### Case 4 — micro-gap ignored

Gap duration:

```text
180 ms
```

Expected:

```text
not a pause candidate
```

### Case 5 — short gap accepted

Gap duration:

```text
400 ms
```

near 12 s.

Expected:

```text
short_gap
```

only if no higher-priority candidate wins.

### Case 6 — overlap avoidance

Natural speaker transition occurs inside a two-speaker overlap region around 12 s.

Strong speech gap occurs at 14 s.

Expected:

```text
14 s gap selected
```

rather than overlap-conflicted transition.

### Case 7 — uninterrupted monologue

No speech gap or speaker change for >30 s.

Expected:

```text
exact hard-max boundary at 30 s
```

### Case 8 — no preferred candidate but later pause

No candidate from 8–18 s.

Strong gap at 20.3 s.

Expected:

```text
20.3 s gap selected
```

rather than waiting toward 30 s.

### Case 9 — final short remainder

Previous boundary leaves 3 seconds at episode end.

If merging keeps previous chunk <=30 s:

```text
merge remainder
```

otherwise:

```text
emit short terminal chunk
```

### Case 10 — deterministic tie

Two same-class candidates equidistant from target.

Expected:

```text
earlier timestamp wins
```

## Real-audio development inspection

Before freezing benchmark segmentation, generate a development report sampling at least:

```text
100 chunk boundaries
```

across multiple episodes.

Ensure the sample includes at least:

```text
20 boundaries involving multi-speaker exchanges
20 boundaries near overlap
20 chunks containing AST-detected background/dominant music
20 long-monologue or low-pause regions
```

Categories may overlap.

Human reviewer marks:

```text
good
acceptable
awkward
bad
```

and optionally provides a short reason.

No fixed quality threshold is required before the first inspection, but the distribution must be reported before the benchmark manifest is frozen.

If parameter tuning occurs, regenerate the entire development manifest under a new configuration fingerprint.

Do not tune after held-out segmentation is frozen.

## Inputs, outputs and failure behavior

## Inputs

* episode duration;
* canonical episode identity;
* Community-1 standard diarization artifact;
* segmentation configuration.

## Outputs

* deterministic chunk manifest;
* boundary diagnostics;
* configuration fingerprint;
* development boundary-review report.

## Failure behavior

If Community-1 diarization is missing, malformed, non-monotonic, or outside episode bounds:

```text
block chunk generation for that episode
```

Do not silently:

* run ASR to infer boundaries;
* add another VAD;
* fabricate speech gaps;
* clamp invalid diarization without reporting it.

If no natural candidate exists, use the defined hard-maximum behavior.

## Exclusions

This task does not:

* introduce Silero or another VAD;
* change Community-1;
* classify music;
* run ASR;
* create transcript truth;
* require grammatical sentence boundaries;
* evaluate ASR quality.
