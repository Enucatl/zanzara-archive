# [P1R-08A] Classify acoustic conditions with AudioSet AST

- Stable ID: P1R-08A
- Executor: Luna
- Kind: Implementation
- Parent: P1R
- Blocked by: P0, P1R-03, P1R-08B, P1R-08C

## Outcome and requirement

Run local `MIT/ast-finetuned-audioset-10-10-0.4593` on the canonical chunk interval to seed non-speaker acoustic-condition metadata for sampling, review prioritization, ASR slices and failure analysis.

## Design and interfaces

Lock repository/revision/checksum, feature extractor, Transformers version, precision and image digest. AST owns music, singing, laughter and other AudioSet events; it never infers speaker count or overlap. Persist model-label-map class IDs/names and raw relevant probabilities. Deterministically window chunks longer than the model preference and freeze aggregation. Derive `has_music`, `music_level` (`none`, `background`, `dominant`, `uncertain`), `has_speech`, `non_speech_activity`, plus deterministic clipping/loudness/silence measurements. `audio_quality` remains a human-reviewable `clean`/`degraded`/`uncertain` label, not an AST claim.

## Bounded steps

1. Implement the pinned local AST adapter and common-chunk preprocessing fingerprint.
2. Store raw AudioSet scores using the locked model label map and deterministic window aggregation.
3. Calibrate/version development-only music mapping using AST speech/music evidence; report reviewed development confusion for none/background/dominant.
4. Expose separate machine-seeded music/quality fields for human correction.

## Inputs, outputs and failure behavior

Input is the same canonical chunk interval sent to ASRs, with documented AST-specific transform. Output is immutable scores, derived condition seed and signal measurements. Missing model/runtime or uncertain evidence remains visible; no alternative classifier or conversion of uncertain to none is allowed.

## Exclusions

No speaker-count/overlap inference, diarization replacement, generic learned quality score, ASR-score sampling, remote API, or silent classifier substitution.

## Acceptance checklist

- [ ] Exact AST checkpoint/revision, feature extractor, runtime and precision are locked; representative Opus-derived RTX 5090 inference succeeds.
- [ ] Raw model-label-map class IDs/names and probabilities are retained.
- [ ] Chunk windowing/aggregation and archive-condition mapping are deterministic, tested and versioned.
- [ ] Music thresholds are calibrated on development only and reviewed confusion is recorded.
- [ ] UI supports human `music_level`/`audio_quality` correction while preserving machine seed.
- [ ] Uncertain output is preserved and P1R-08 speaker fields are not written.

## Verification commands

Run AST adapter/windowing/mapping fixtures and focused persistence/UI tests; perform a private local RTX 5090 smoke inference and run CPU tests without model download.

## Evidence and documentation

Record model/checkpoint/runtime/preprocessing hashes, locked label-map version, development calibration/confusion summary, signal-measurement schema and private GPU smoke hash.

## Stop conditions and completion rule

Stop on unavailable/incompatible weights, unpinned label map, uncalibrated threshold, or inability to preserve uncertain output. Complete after local smoke and all deterministic fixture evidence pass.
