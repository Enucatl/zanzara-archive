# [P1R-08B] Prepare dedicated music calibration review workflow

- Stable ID: P1R-08B
- Executor: Luna
- Kind: Implementation
- Parent: P1R
- Blocked by: P0, P1R-03

## Outcome and requirement

Give the operator a dedicated web page that plays canonical development clips
and durably records human music labels, so P1R-08A (#99) can obtain its missing
reviewed calibration evidence. The legacy P1 word-level annotation editor is
not this workflow. This prerequisite must run before P1R-10 and must not depend
on completion of P1R-08A's human calibration gate.

## Design and interfaces

Use the existing Python/FastAPI/Jinja/vanilla-JavaScript stack with a dedicated
calibration route and documented launch command. Accept or prepare a frozen
private review batch from canonical chunks and an explicit episode-level
partition assignment. Validate development-only membership, source/chunk hashes,
intervals and segmentation provenance. Do not invent reviewed labels or silently
choose held-out episodes. Persist the batch fingerprint and preserve its episode
assignment for later P1R-11 membership reconciliation.

Show one bounded audio clip at a time with play/pause/replay, previous/next,
progress, reviewer name, optional note, four initially unselected labels
(`none`, `background`, `dominant`, `uncertain`), and save-and-next. Display concise
listening guidance. Hide AST predictions and scores throughout human labeling.
Do not require transcripts, word timings, speaker IDs or audio-quality labels.

Save append-only decisions with batch/chunk/source identity, label, reviewer,
server-recorded UTC review time, note and revision. Resume saved progress and
reject stale writes without losing an existing decision. Export a private,
deterministic review artifact with provenance and reviewed/unreviewed counts
that can be joined to immutable AST scores for subsequent threshold fitting
and confusion reporting. Export must not imply calibration acceptance.

## Bounded steps

1. Implement validated development-batch preparation/import and private media
   access restricted to each registered canonical interval.
2. Implement the dedicated calibration page, playback/navigation and durable
   label persistence with resume and conflict handling.
3. Implement private review export and document batch preparation, launch URL,
   human listening steps, export, and the remaining P1R-08A acceptance gate.

## Inputs, outputs and failure behavior

Input is frozen corpus metadata, existing canonical chunks or deterministic
segmentation inputs, and explicit episode partitions; output is a private
review batch, bounded playable clips and append-only human decisions/export.
Reject held-out/unknown membership, invalid intervals, missing provenance,
changed batch content and stale revisions. Missing source audio is visible
and must not allow a false successful review. Preserve uncertain labels.

## Exclusions

No legacy word editor reuse as the user-facing flow, full P1R-10 transcription
UI, automatic labels or approval, model training, threshold tuning, held-out
scoring, remote services, archive-wide processing, or phase release. Completing
this issue does not complete #99; actual human listening remains required.

## Acceptance checklist

- [ ] A dedicated calibration URL and executable launch/preparation commands
  are documented; no manual chunk-ID entry is needed during review.
- [ ] Batch validation proves development-only episode membership and canonical
  source/interval/provenance identity; invalid inputs fail without partial output.
- [ ] Browser verification covers bounded playback/replay, all four labels,
  save-and-next, navigation, guidance and prediction-blind rendering.
- [ ] Decisions survive restart/reload, remain append-only, and stale writes
  cannot overwrite a review; no label is preselected for an unreviewed clip.
- [ ] Export preserves reviewer/time/revision/provenance, uncertain decisions,
  and truthful reviewed/unreviewed counts without claiming calibration success.
- [ ] Focused failure tests cover held-out input, invalid/missing audio, unsafe
  paths, changed batch identity and concurrent/stale saves.

## Verification commands

Run `uv run ruff check .`, `uv run ruff format --check .`, focused pytest tests
for batch validation/API/persistence/export, browser tests or reproducible
browser automation for the complete review interaction, and
`node planning/validate.mjs`. Synthetic audio/labels are appropriate for software
verification and must be identified as synthetic; they are not calibration data.

## Evidence and documentation

Record the commit, exact checks/results, private browser evidence and an operator
runbook with a concrete launch command, review URL, input schema and export
command. Preserve the already prepared acoustic-condition listening guidance.
Publish only sanitized implementation evidence; real audio and human labels stay
private. Follow the repository implementation skill: commit and push to main,
verify the remote commit, and record acceptance on this child issue.

## Stop conditions and completion rule

Complete when the usable review workflow and its software acceptance checks
pass. Do not mark P1R-08A Done or manufacture human calibration evidence.
Missing actual human decisions is the remaining #99 gate, not a reason to
leave verified review tooling incomplete.
