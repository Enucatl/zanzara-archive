# [P1R-08C] Generate deterministic development calibration batches

- Stable ID: P1R-08C
- Executor: Luna
- Kind: Implementation
- Parent: P1R
- Blocked by: P0, P1R-03

## Outcome and requirement

Make the P1R-08B calibration workflow usable without hand-writing chunk IDs.
Generate a private music-review batch from the frozen corpus and an explicit
episode-level development/held-out split. The generated batch is input to the
dedicated calibration page and remains development-only.

## Design and interfaces

Add `zanzara calibration generate --split ... --manifest ... --batch-id ...
--clips-per-episode ... --output ...`. Validate that the split assigns every
frozen corpus episode exactly once and that development and held-out sets are
disjoint. Apply the deterministic P1R chunk policy to development episodes
(8-second preferred minimum, 12-second target, 18-second preferred maximum
and 30-second hard maximum), then select evenly spaced clips per episode. Keep
source hashes, source-relative bounds, segmentation
version/configuration/fingerprint, split and corpus manifest hash.
Selection must not inspect AST scores, ASR scores or human labels. The existing
`calibration prepare` command then validates/imports the generated artifact.

## Bounded steps

1. Validate the explicit split against the frozen corpus.
2. Generate and deterministically subsample development chunks.
3. Write the private batch JSON and document the preparation command.

## Inputs, outputs and failure behavior

Input is the frozen corpus manifest and a private split JSON. Output is a
private batch JSON suitable for P1R-08B. Invalid or incomplete splits, invalid
clip counts and missing provenance fail before output is published.

## Acceptance checklist

- [ ] Split validation rejects missing, duplicate, unknown and overlapping
  episode assignments before writing output.
- [ ] Generated output is deterministic for the same manifest, split,
  configuration and batch ID; every clip is development-only and canonical.
- [ ] Output contains the split and provenance needed by P1R-08A/P1R-11.
- [ ] CLI and focused tests document generation, validation and failure paths.

## Verification commands

Run focused calibration tests, `uv run ruff check .`,
`uv run ruff format --check .`, and `node planning/validate.mjs`.

## Evidence and documentation

Record the commit and exact checks. The generated batch and split remain private;
public evidence contains only sanitized counts and hashes.

## Exclusions

No AST inference, threshold fitting, human labels, held-out scoring, or phase
release. Those remain P1R-08A and operator gates.

## Stop conditions and completion rule

Stop on any split or provenance mismatch. Complete when deterministic generation,
focused tests and the documented private handoff pass; this does not create
human labels or complete P1R-08A.
