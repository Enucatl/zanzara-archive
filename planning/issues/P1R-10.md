# [P1R-10] Replace annotation UI with chunk-centric transcription review

- Stable ID: P1R-10
- Executor: Luna
- Kind: Implementation
- Parent: P1R
- Blocked by: P0, P1R-07, P1R-08, P1R-09

## Outcome and requirement

Deliver a keyboard-efficient review interface for human-created chunk truth, not manual word-boundary correction.

## Design and interfaces

Show episode/time/duration, compact waveform/timeline, condition tags, clearly separate Parakeet/Whisper/Voxtral/Qwen drafts, editable final transcript, speaker streams, unintelligible marker and condition corrections. Support play/pause, loop, ±2–3 seconds, previous/next chunk, transcript focus and save/approve shortcuts.

## Bounded steps

1. Implement chunk audio controls and keyboard operation.
2. Implement versioned reference/speaker/condition editing with conflict response.
3. Preserve immutable candidates and graceful Qwen-unavailable state.

## Inputs, outputs and failure behavior

Input is a chunk, hypotheses and reference revision. Output is append-only reviewed reference state. Revision conflict returns a clear non-overwriting response.

## Exclusions

No token timestamp editor, automatic approval, diarizer-label acceptance, public transcript display, or archive-wide annotation run.

## Acceptance checklist

- [ ] Browser tests cover clean, multi-speaker, overlap and candidate-disagreement chunks.
- [ ] Qwen outage, reviewer correction and revision conflict are handled.
- [ ] Core playback/navigation/save operations have keyboard shortcuts.
- [ ] Candidates and final gold remain visibly and persistently distinct.

## Verification commands

Run focused browser/UI tests plus relevant API and persistence tests.

## Evidence and documentation

Record synthetic screenshots/test traces and shortcut/reference-state documentation.

## Stop conditions and completion rule

Stop if reviewers must enter word boundaries or a conflict can overwrite another revision. Complete after required browser paths pass.
