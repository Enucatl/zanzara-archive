# [P2-07] Human: cross-episode labels and frozen voice splits

- Stable ID: P2-07
- Executor: Human
- Kind: Operator
- Parent: P2
- Blocked by: P1, P2-06

## Outcome and requirement

Candidate excerpts from the same frozen 20; output reviewed pair/identity labels and leakage-audited split manifests.

## Design and interfaces

Use [E3](../EVALUATION.md#e3--voice-labels-splits-and-scoring), [D7](../SYSTEM-DESIGN.md#d7--voice-retrieval-and-identity) and the existing contracts/modules produced by completed prerequisites. The implementation issue establishes only interfaces within this scope; preserve compatible earlier contracts. See [execution rules](../GITHUB-SETUP.md#g7--luna-implementation-handoff-and-release-rules) for selection and evidence.

## Prerequisites

Parent: [P2](P2.md). Required completed blockers: [P1](P1.md), [P2-06](P2-06.md). The preceding phase must have a current Sol PASS and explicit user release. This issue does not depend on its own parent closing.

## Bounded steps

1. Listen to recurring non-host and host appearances plus difficult negative pairs; label same/different/uncertain with private audio evidence.
2. Freeze identity-grouped calibration/held-out partitions and eligible query/gallery lists before fusion training.
3. Record class/group/query counts, excluded ambiguities, host separation and whether calibration evidence meets E3.

## Inputs, outputs and failure behavior

Candidate excerpts from the same frozen 20; output reviewed pair/identity labels and leakage-audited split manifests. Preserve source/model/configuration provenance in outputs and fail without publishing partial artifacts when validation fails. Unreviewed labels, invalid splits or no eligible retrieval queries cannot satisfy the evaluation gate.

## Exclusions

No Luna identity judgments, demographic inference, automatic enrollment or corpus expansion.

## Acceptance checklist

- [ ] Every binary label has human provenance and both source/episode-speaker hashes.
- [ ] No identity/appearance leakage crosses calibration and held-out; hosts are separately reported.
- [ ] Insufficient evidence is explicit and keeps scores uncalibrated; missing eligible held-out retrieval evidence remains a release blocker.
- [ ] Required evidence below is linked and applies to the reviewed commit/configuration.

## Verification commands

```bash
uv run zanzara evaluation validate-voice-labels --labels "$ZANZARA_VOICE_LABELS" --split "$ZANZARA_VOICE_SPLIT"
```

The operator performs the action/review; CLI validation checks format and completeness, never substitutes for human judgment. If a required validation command is missing, request a bounded Luna follow-up rather than pretending this Human task implemented it.

## Evidence and documentation

Record exact commands/results, reviewed commit, artifact/source/model/split hashes where applicable, and the private evidence path. Update the relevant interface/runbook documentation for implemented behavior. Public issues/PRs contain sanitized aggregate results and synthetic examples only. Include the human actor, action date and explicit decision; never publish credentials or private annotations.

## Stop conditions and completion rule

Unreviewed labels, invalid splits or no eligible retrieval queries cannot satisfy the evaluation gate. Complete only when the human action and acceptance evidence are recorded. Keep [P2](P2.md) open for Sol review and user release.
