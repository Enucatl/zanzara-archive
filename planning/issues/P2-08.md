# [P2-08] Encoder and ensemble evaluation with conditional calibration

- Stable ID: P2-08
- Executor: Luna
- Kind: Evaluation
- Parent: P2
- Blocked by: P1, P2-07

## Outcome and requirement

Frozen human voice labels, gallery/splits and three-model candidate pipeline; output comparison/calibration artifacts and reports.

## Design and interfaces

Use [E3](../EVALUATION.md#e3--voice-labels-splits-and-scoring), [E6](../EVALUATION.md#e6--operational-measurements-and-report-format), [E7](../EVALUATION.md#e7--gates-and-expansion-checks) and the existing contracts/modules produced by completed prerequisites. The implementation issue establishes only interfaces within this scope; preserve compatible earlier contracts. See [execution rules](../GITHUB-SETUP.md#g7--luna-implementation-handoff-and-release-rules) for selection and evidence.

## Prerequisites

Parent: [P2](P2.md). Required completed blockers: [P1](P1.md), [P2-07](P2-07.md). The preceding phase must have a current Sol PASS and explicit user release. This issue does not depend on its own parent closing.

## Bounded steps

1. Evaluate each encoder alone and the full ensemble with identical query/gallery eligibility and host/non-host breakdowns.
2. Implement E3 logistic fusion only when minimum grouped evidence exists; otherwise retain explicitly uncalibrated rank fusion.
3. Report recall/MRR, candidate-union recall, ROC/EER validity, threshold counts and grouped uncertainty; freeze all training choices before held-out scoring.

## Inputs, outputs and failure behavior

Frozen human voice labels, gallery/splits and three-model candidate pipeline; output comparison/calibration artifacts and reports. Preserve source/model/configuration provenance in outputs and fail without publishing partial artifacts when validation fails. Failed retrieval target, invalid split or unsupported probability claims require remediation and block release.

## Exclusions

No automatic merges, cascade optimization or threshold relaxation.

## Acceptance checklist

- [ ] Eligible held-out cross-episode Recall@10 >=80%, with host/non-host counts and limitations.
- [ ] No held-out labels fit weights, standardization or thresholds; raw and fused scores remain inspectable.
- [ ] Sparse verification evidence is reported without invented probabilities or reliable EER claims.
- [ ] Required evidence below is linked and applies to the reviewed commit/configuration.


Add the named focused tests/CLI commands in this issue if they do not yet exist; P0-01 establishes common uv/Ruff/pytest commands. Run relevant CPU checks plus the explicitly required real GPU/integration/evaluation actions. Do not treat a mocked model response as measured model quality.

## Evidence and documentation

Failed retrieval target, invalid split or unsupported probability claims require remediation and block release. Complete only after the required PR is merged and every acceptance item is satisfied; a draft/open PR alone is not completion. Keep [P2](P2.md) open for Sol review and user release.
