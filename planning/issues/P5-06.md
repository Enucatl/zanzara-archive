# [P5-06] Produce and index the initial 20 transcripts

- Stable ID: P5-06
- Executor: Luna
- Kind: Implementation
- Parent: P5
- Blocked by: P3-03

Active under the 2026-09-28 working plan; direct prerequisites below replace phase-wide release gates.

## Outcome and requirement

Produce timed, speaker-attributed transcripts and FTS5 rows for the frozen 20 episodes, starting as soon as the indexer works on the existing real transcript.

## Design and interfaces

Reuse the working Parakeet ASR, Community-1 diarization, attribution and P3-03 indexer. One episode already has completed stage artifacts; process the rest in bounded, resumable batches using the existing per-episode CLI/worker. Use the current timed production baseline without waiting for the separate ASR comparison. If that comparison later justifies a different production model, reprocess only affected stages. Count indexed episodes and words; report any stage failures. Run alongside search API and website implementation.

Use the [working plan](../README.md), relevant [design contract](../SYSTEM-DESIGN.md) and [evaluation guidance](../EVALUATION.md). Earlier closed issue checklists are historical, not new prerequisites.

## Bounded steps

1. Index the existing attributed episode and confirm its FTS5 count.
2. Process the remaining frozen episodes through missing ASR, diarization, attribution and indexing stages, resuming completed work.
3. Reconcile stage and index counts for all 20, with concrete failure/retry actions.

## Inputs, outputs and failure behavior

Use the frozen manifest and registered source paths. Persist stage outputs and index only complete attribution artifacts with original offsets. A missing model service, unreadable source or failed episode remains visible for retry; never treat a partial episode as indexed.

## Exclusions

Voice retrieval, browser completion, the ASR pilot, cloud comparisons and remote access do not block initial transcript production.

## Acceptance checklist

- [ ] Every frozen episode has a timed attribution artifact and corresponding FTS5 rows, or an explicit failed/blocked stage with a retry action.
- [ ] Index counts and episode IDs reconcile to complete attribution artifacts; repeated processing does not duplicate rows.
- [ ] One real query finds text from the newly indexed episodes with the correct original episode and time offsets.

## Verification commands

Use the stage/index status commands and one real indexed-query check. Smoke a service only if its runtime changed or it fails. No routine checkpoint/corpus rehash or unrelated benchmark rerun.

## Evidence and documentation

Record the processing command/commit, per-stage episode counts, failed IDs/reasons and a private artifact/index path. Keep real audio, text and identities private.

## Stop conditions and completion rule

Complete when the 20-episode accounting and real indexed-query check pass. A concrete missing source/service or failed stage is an actionable blocker. Later P5 acceptance covers browser, voice, quality and restore evidence.
