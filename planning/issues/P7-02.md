# [P7-02] Human: cross-year labels and historical retrieval evaluation

- Stable ID: P7-02
- Executor: Human
- Kind: Operator
- Parent: P7
- Blocked by: P6, P7-01

## Outcome and requirement

Historical canary candidates/audio and existing voice evaluation harness; output reviewed cross-year labels and quality verdict.

## Design and interfaces

Use [E3](../EVALUATION.md#e3--voice-labels-splits-and-scoring), [E7](../EVALUATION.md#e7--gates-and-expansion-checks) and the existing contracts/modules produced by completed prerequisites. The implementation issue establishes only interfaces within this scope; preserve compatible earlier contracts. See [execution rules](../GITHUB-SETUP.md#g7--luna-implementation-handoff-and-release-rules) for selection and evidence.

## Prerequisites

Parent: [P7](P7.md). Required completed blockers: [P6](P6.md), [P7-01](P7-01.md). The preceding phase must have a current Sol PASS and explicit user release. This issue does not depend on its own parent closing.

## Bounded steps

1. Human reviews cross-year same/different/uncertain pairs and recurring non-hosts/difficult negatives, preserving source/identity provenance.
2. Freeze leakage-audited canary query/gallery/reference manifests before scoring with the existing CLI.
3. Review full-ensemble/per-encoder Recall@10, uncertainty, eligible counts and year/quality breakdown; retain uncalibrated status if labels cannot support fitting.

## Inputs, outputs and failure behavior

Historical canary candidates/audio and existing voice evaluation harness; output reviewed cross-year labels and quality verdict. Preserve source/model/configuration provenance in outputs and fail without publishing partial artifacts when validation fails. Failed target or insufficient valid labels blocks P7-03; request bounded Luna remediation if tooling needs fixes.

## Exclusions

No bulk authorization, held-out fitting or automatic name inference.

## Acceptance checklist

- [ ] Historical held-out eligible Recall@10 >=80% and relevant E7 checks pass.
- [ ] Cross-year labels are human-reviewed and insufficient evidence cannot be reported as pass.
- [ ] Required evidence below is linked and applies to the reviewed commit/configuration.

## Verification commands

```bash
uv run zanzara evaluation validate-voice-labels --labels "$ZANZARA_HISTORICAL_LABELS" --split "$ZANZARA_HISTORICAL_SPLIT"
uv run zanzara evaluation run --suite voice --labels "$ZANZARA_HISTORICAL_LABELS" --split "$ZANZARA_HISTORICAL_SPLIT" --output "$ZANZARA_HISTORICAL_REPORT"
```

The operator performs the action/review; CLI validation checks format and completeness, never substitutes for human judgment. If a required validation command is missing, request a bounded Luna follow-up rather than pretending this Human task implemented it.
